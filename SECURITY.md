# Security Policy

## Supported versions

Security fixes are applied to the current stable release line.

## Reporting a vulnerability

Do not publish an unpatched vulnerability, exploit, credential, private key, token, personal database, or other sensitive material in a public issue.

Report security-sensitive findings privately to:

- thedevorger.alekrythae.dev@gmail.com

Include the affected version, reproduction steps, expected impact, and the smallest safe proof of concept needed to reproduce the issue. Do not include real user secrets or unrelated personal data.

## Repository hygiene

Runtime databases, logs, backups, local environment files, credentials, private keys, signing material, and generated build output are excluded from source control. Canonical source templates and application assets are intentionally tracked.
